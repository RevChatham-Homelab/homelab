# Appendix A – Reference

## Purpose

This appendix provides a quick reference to commonly used CBART terminology, generated artifacts, and directory structures.

It is intended as a companion reference for users and administrators and does not replace the detailed guidance provided throughout the User Manual.

---

# Recovery Point Naming Convention

Recovery Points use the following naming format:

```
RP-YYYYMMDD-###
```

Example:

```
RP-20260721-003
```

Where:

- **YYYY** — Year
- **MM** — Month
- **DD** — Day
- **###** — Sequential Recovery Point number

---

# Primary Recovery Point Artifacts

| Artifact | Purpose |
|----------|---------|
| Manifest | Inventory of the Recovery Point contents |
| Verification Report | Records verification results |
| Execution Log | Chronological record of Recovery Point creation |
| Checksums | File integrity verification |
| Documentation Archive | Backup of project documentation |
| Docker Backup | Docker Compose files and supporting configuration |
| Proxmox Information | Host, storage, VM, and backup inventory |

---

# Recovery Point Directory Structure

```
RP-YYYYMMDD-###

├── checksums/
├── docker/
├── documentation/
├── logs/
├── manifest/
├── proxmox/
└── verification/
```

# Common Terminology

| Term | Description |
|------|-------------|
| Recovery Point | A complete snapshot of the documented environment |
| Manifest | Inventory of Recovery Point contents |
| Verification | Process used to validate Recovery Point integrity |
| Execution Log | Chronological record of application activity |
| Artifact | A file generated by CBART |
| Repository | The CBART project directory |
| Administrator | User responsible for maintaining CBART |
| Standards | Documents governing project consistency |
